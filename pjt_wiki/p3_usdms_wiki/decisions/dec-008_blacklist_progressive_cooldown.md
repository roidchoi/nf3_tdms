# [ADR-008] USDMS 블랙리스트 단순 누계 기반 누진 쿨다운 도입

- **상태**: Accepted (2026-07-14)
- **대상**: `p3_usdms` 블랙리스트 관리 모듈

---

## 1. 맥락 (Context)
- 쿨다운(7일)이 경과하여 블랙리스트에서 자동 해제된 종목이 여전히 상장폐지(`DELISTED`) 등의 원인이 해소되지 않은 경우, 다음 수집 시점에 다시 에러를 내며 블랙리스트로 재차단되는 루프가 매주 반복되었습니다.
- 이 과정에서 SEC EDGAR 및 yfinance API 호출이 불필요하게 낭비되고, 가치평가 및 지표 계산 시점에 자원이 낭비되는 비효율이 있었습니다.
- 영구적 오류와 일시적 오류를 매번 파싱하고 판별하려다 보니 API 응답 포맷 변화 등에 대한 대응이 까다로워지고 로직이 비대화되는 한계가 존재했습니다.

---

## 2. 결정 (Decision)
- **오류 사유 분류 배제**: 오류 사유(Reason Code)와 무관하게 모든 수집 실패 차단에 대해 동일한 정책을 일관되게 적용합니다.
- **단순 누계 기반 누진 쿨다운 (Cumulative Cooldown)**:
  - 블랙리스트 재차단 누적 횟수(`re_blocked_count`) 컬럼을 신규 배치하여 해제 후 다시 차단된 횟수를 트래킹합니다.
  - 재차단 누계 횟수에 따라 쿨다운 대기 기간을 점진적으로 증가시킵니다.
    - **1회차 차단 (최초)**: 1일 유예 후 자동 해제
    - **2회차 차단**: 7일 유예 후 자동 해제
    - **3회차 차단**: 30일 유예 후 자동 해제
    - **4회차 차단**: 60일 유예 후 자동 해제
    - **5회차 차단 (영구 제외)**: 자동 해제 대상에서 영구 제외 (`is_permanently_blocked = TRUE` 마킹)
- **자동 vs 수동 해제 동작의 격리**:
  - 스케줄러에 의한 자동 해제(`auto_release_expired_blocks`) 시에는 누적 카운터를 보존하여 다음 차단 시 누진 적용되게 합니다.
  - 관리자에 의한 명시적 수동 해제(`release_blacklist` with `reset_counters=True`) 시에는 `re_blocked_count`와 `is_permanently_blocked` 플래그를 0 및 FALSE로 완전 리셋합니다.

---

## 3. 결과 (Consequences)
- **로직 경량화**: API 예외 메시지나 HTTP 응답 상태를 복잡하게 파싱하고 대응하던 코드가 완전히 단순화되어 유지보수성이 크게 향상되었습니다.
- **데이터 무결성 방어**: yfinance 등 스크래퍼 오탐지로 인해 정상 주식이 일시 차단되더라도 최대 4회에 걸쳐 복구 기회를 가집니다. (오판으로 인한 정상 종목 영구 누락 리스크 0% 실현)
- **리소스 최적화**: 구제 불능 종목(실제 상장폐지 등)은 결국 5회차에 도달하여 자동 해제 대상에서 영구 격리되므로, API 호출 낭비를 장기적으로 완벽하게 방어합니다.
- **SQL 단일 쿼리화**: `re_blocked_count`별 대기 시간을 CASE WHEN 조건이나 OR 연산자로 병합하여, 스케줄러 기동 시 단 한 번의 인덱스 검색만으로 해제 대상을 파악하도록 쿼리 튜닝을 완수했습니다.
