# Project Agent Rules (NF3 TDMS)

## 1. 도커(Docker) 명령 실행 및 파괴적 작업 승인 규칙

1. **도커 중단/재빌드 명령어 자의적 자동 실행 엄격 금지**:
   - `docker compose down`, `docker compose build`, `docker compose up --build`, `docker compose stop`, `docker compose restart`, `docker rm`, `docker rmi` 등 컨테이너/이미지를 중단하거나 재빌드하는 모든 파괴적/중단적 명령어는 권한 허용 여부와 무관하게 **에이전트가 단독 판단으로 자동 실행하는 것을 영구 금지**합니다.
   
2. **사전 승인 프로토콜**:
   - 상기 도커 중단/재빌드 작업이 필요한 경우, 에이전트는 반드시 **(1) 구체적인 작업 목적**, **(2) 파이프라인/수집 태스크에 미치는 영향**, **(3) 예상되는 결과**를 사용자에게 명확히 설명하고, **사용자의 명시적 승인("승인함", "실행해" 등)**을 득한 후에만 해당 명령어를 실행합니다.

3. **안전한 모니터링 명령 조치**:
   - `docker compose ps`, `docker compose logs` 등 정보 조회 목적의 단순 모니터링 명령어는 사전 검증용으로만 안전하게 활용합니다.

---

## 2. OS/호스트 환경 검증 및 세션 보호 행동 수칙

1. **자의적 경로/명령어 추정 절대 금지 및 사전 100% 실측 의무화**:
   - Windows/WSL 호스트 파일 경로(예: `.vhdx` 위치), WSL 인스턴스명, 명령어 옵션 등을 일반 상식이나 튜토리얼 지식으로 추정하여 제안하는 것을 절대 금지합니다.
   - 반드시 `/mnt/c/` 스캔, `wsl.exe -l -v` 실행 등 터미널 사전 조회를 통해 **100% 팩트로 검증된 실제 절대 경로 및 인스턴스명만 제안**해야 합니다.

2. **IDE 세션 및 구동 환경 단절 예방**:
   - `wsl --shutdown`과 같이 개발용 가상환경(Ubuntu) 및 IDE Remote 커넥션을 통째로 단절시키는 파괴적 전역 명령 제안을 금지합니다.
   - 가상머신 정지가 필요할 경우, IDE가 작동 중인 배포판을 제외하고 특정 대상 인스턴스만 개별 정지(`wsl -t <distro>`)하는 우회 수칙을 우선 적용합니다.

3. **대화형 툴/명령어 가이드 제공 원칙**:
   - `diskpart`와 같은 대화형 프롬프트 바이너리나 복합 터미널 명령어 제안 시, 명령어 씹힘이나 무반응 예외를 방지하기 위해 **반드시 1줄씩 순차 실행 가능한 단계별 가이드로 분리하여 제공**합니다.
