# [P2DEC-006] KIS 마스터 API 주식수 누락 시 DB 이전 데이터 Fallback(대체) 적용

## 1. 배경 및 문제 의식
* KIS API 측의 마스터 제공 불완전성이나 일시적인 네트워크 순서 이슈로 마스터 파일 다운로드 실패/오류 시, 상장주식수(`listed_shares`)가 `0`으로 유입되어 `stock_info` 테이블 및 `daily_market_cap` 테이블에 상장주식수 및 시가총액이 `0`으로 누적 적재되는 현상이 발견되었습니다. (예: 005930 삼성전자 종목의 2026-05-22 ~ 2026-06-15 시가총액 0 적재 장애)
* 시가총액이 0으로 잘못 적재되면 과거 시가총액을 참조하여 종목의 권리락/증자 의심 여부를 추출하는 보정 스크립트(`backfill_pipeline.py`) 및 재무 분석 엔진이 비정상 수치를 리턴하게 되어 데이터 무결성이 훼손됩니다.

## 2. 해결 방안 및 의사결정
* **대체(Fallback) 매커니즘 도입**: KIS OpenAPI로부터 수집한 마스터 또는 상장주식수가 `0` 이하로 유입되는 상황이 발생할 경우, 전체 적재 파이프라인을 중단하는 대신 **DB 내 해당 종목의 최근 10일 영업일 이내 적재된 마지막 정상 상장주식수를 조회하여 대체(Fallback)**하기로 결정하였습니다.
* **영향성 최소화**: 일시적 API 제공 오류로 인한 시가총액 데이터 오염을 예방하며, 이미 정상 데이터가 채워져 있는 과거 구간의 데이터 안정성을 지속적으로 유지합니다.

## 3. 세부 설계 및 구현 내용
* **수정 위치**: `daily_task.py` 내의 `mc_records` 빌드 루프 (`DailyTask.run()`)
* **동작 순서**:
  1. `stock.get("listed_shares", 0)`이 `0` 이하인지 판별합니다.
  2. 만약 `0` 이하인 경우, `market_cap_repo.get_daily_market_cap(stk_cd, start_date - 10일, start_date)`을 통해 최근 10일 동안의 이력을 날짜 오름차순으로 조회합니다.
  3. 이력이 존재하는 경우, 가장 마지막 인덱스(`[-1]`)의 `listed_shares` 값을 상장주식수로 적용하고 Info 로그를 출력합니다.
  4. 조회에 실패하거나 DB에 기존 이력이 없는 경우에만 최종적으로 상장주식수를 `0`으로 가드 처리합니다.

## 4. 기대 효과
* KIS API의 간헐적 장애 상황 하에서도 `daily_market_cap`과 `stock_info` 테이블의 데이터 정합성을 항시 확보하여 자가 치유(Self-Healing) 능력을 가집니다.
