# TDMS 프로젝트 의존성 관리 지침

> **적용 범위**: p1_shared, p2_kdms, p3_usdms, p4_manager 모든 서브프로젝트
> **환경**: WSL 2 (Ubuntu 24.04 LTS)

---

## 1. 기본 원칙

- **네이티브 Python 금지**: 시스템(OS 기본) Python은 절대 사용하지 않는다. 모든 작업은 반드시 해당 프로젝트의 Conda 가상환경 안에서 수행한다.
- **requirements.txt 통한 설치**: 패키지를 직접 설치(`uv pip install <패키지>`)하는 것을 금지한다. 반드시 `requirements.txt`를 먼저 수정한 후 파일을 통해 설치한다.
- **pip 사용 금지**: `pip install` 대신 **반드시 `uv pip install`** 을 사용한다.
- **Conda는 환경 관리 전용**: `conda install`로 라이브러리를 설치하지 않는다. Conda는 가상환경 생성(Python 버전 고정)에만 사용하고, 패키지 설치는 전부 `uv`로 처리한다.

## 3. 최초 환경 구성 절차

새로운 서브프로젝트 구현을 시작할 때 아래 순서를 따른다.

### Step 1: requirements.txt 작성

구현에 필요한 전체 의존성을 먼저 파악하여 `requirements.txt`를 작성한다.

```
# tdms_core/p1_shared/requirements.txt 예시
psycopg2-binary>=2.9
requests>=2.32
python-dotenv>=1.1
holidays>=0.46
rich>=13.0
pytest
pytest-asyncio
pytest-mock
```

### Step 2: Conda 가상환경 생성 (Python 버전 고정)

```bash
conda create -n tdms_p1_env python=3.12 -y
conda activate tdms_p1_env
```

### Step 3: uv를 통한 의존성 설치

```bash
uv pip install -r requirements.txt
```

### Step 4: p1_shared editable install (p2·p3·p4 환경에만 해당)

p2_kdms, p3_usdms, p4_manager 환경에서는 p1_shared 패키지를 editable install로 추가한다.
이 항목도 requirements.txt에 명시한다.

```
# tdms_core/p2_kdms/requirements.txt 예시
-e ../p1_shared    # p1_shared 공통 모듈 editable install
fastapi>=0.111
uvicorn>=0.29
...
```

설치 명령:

```bash
conda activate tdms_p2_env
uv pip install -r requirements.txt
```

## 4. 패키지 추가·업그레이드 절차

서브프로젝트 개발 도중 새 패키지가 필요하거나 버전을 변경해야 할 경우 아래 순서를 반드시 따른다.

```
[금지] conda activate tdms_p1_env && uv pip install <패키지>  ← 직접 설치 금지

[올바른 절차]
1. requirements.txt에 해당 패키지(버전 포함) 추가 또는 수정
2. uv pip install -r requirements.txt 로 설치
3. git에 requirements.txt 변경사항 커밋
```

## 5. 가상환경 재현 (다른 PC 또는 CI 환경)

requirements.txt가 정확히 관리되면 어느 환경에서든 동일하게 재현할 수 있다.

```bash
conda create -n tdms_p1_env python=3.12 -y
conda activate tdms_p1_env
uv pip install -r requirements.txt
```

> **주의**: GPU 가속 ML 라이브러리(PyTorch 등)가 필요한 경우에만 예외적으로 `conda install`을 사용한다. 이 경우에도 해당 패키지를 requirements.txt에 주석으로 명시한다.

## 6. 환경 오염 감지 체크

작업 전 현재 어느 환경인지 반드시 확인한다.

```bash
# 현재 활성 환경 확인
conda info --envs

# 설치된 패키지와 requirements.txt 차이 확인
uv pip freeze | diff - requirements.txt
```

## 7. 에이전트(Agent) 터미널 실행 시 가상환경 사용 지침

### 7.1 문제: conda activate는 비대화형 셸에서 동작하지 않는다

에이전트가 `run_command` 도구로 터미널 명령을 실행할 때, 셸은 **비대화형(non-interactive)** 서브프로세스로 실행된다.
이 경우 `conda activate`는 셸 훅(hook)이 초기화되지 않아 **환경이 실제로 전환되지 않는다**.

```bash
# ❌ 잘못된 방법 — conda activate가 무시됨
conda activate tdms_p1_env
python script.py   # ← 여전히 base 또는 시스템 Python으로 실행됨
```

### 7.2 올바른 방법: conda run 사용

`conda run -n <환경명> <명령>` 형식을 사용한다.
이 명령은 활성화 없이 지정한 환경의 Python·바이너리를 직접 실행하므로 비대화형 셸에서도 정확하게 동작한다.

```bash
# ✅ 올바른 방법 — conda run으로 환경 지정 후 실행
conda run -n tdms_p1_env python script.py
conda run -n tdms_p1_env pytest tests/ -v
conda run -n tdms_p1_env uv pip install -r requirements.txt
```

### 7.3 대안: 인터프리터 절대경로 사용

환경 내 Python 인터프리터의 절대경로를 직접 지정하는 방법도 사용할 수 있다.

```bash
# Miniforge 기본 설치 경로 기준 (환경에 따라 경로 확인 필요)
~/miniforge3/envs/tdms_p1_env/bin/python script.py
~/miniforge3/envs/tdms_p1_env/bin/pytest tests/ -v
~/miniforge3/envs/tdms_p1_env/bin/uv pip install -r requirements.txt

# 실제 경로 확인 방법
conda run -n tdms_p1_env which python
```

### 7.4 에이전트 명령 실행 규칙 요약

에이전트가 터미널 명령을 실행할 때 아래 규칙을 따른다.

| 상황 | 명령 형식 |
|---|---|
| 스크립트·모듈 실행 | `conda run -n tdms_p{n}_env python <script>` |
| 테스트 실행 | `conda run -n tdms_p{n}_env pytest tests/ -v` |
| 패키지 설치 | `conda run -n tdms_p{n}_env uv pip install -r requirements.txt` |
| 환경 확인 | `conda run -n tdms_p{n}_env python --version` |

### 7.5 환경 존재 여부 사전 확인

명령 실행 전 해당 환경이 존재하는지 먼저 확인한다. 존재하지 않으면 §3 절차를 따라 먼저 환경을 생성한다.

```bash
# 환경 존재 여부 확인
conda env list | grep tdms_p1_env

# 환경이 없으면 §3 Step 2 절차 실행
conda create -n tdms_p1_env python=3.12 -y
conda run -n tdms_p1_env uv pip install -r requirements.txt
```
