# [P2ERR-004] KIS 마스터 수집 장애로 인한 상장주식수 및 시가총액 0 누적 적재 에러

## 1. 에러 현상 및 환경
* **발생 환경**: KDMS 일일 수집기 배치가 실행되는 환경 (WSL2 / Ubuntu 24.04 LTS)
* **장애 내용**: 특정 종목(예: 삼성전자 005930)의 `2026-05-22` ~ `2026-06-15` 구간의 `daily_market_cap` 테이블 내 `mkt_cap`과 `listed_shares` 컬럼 값이 `0`으로 기형적 적재되는 현상 발생.

## 2. 발생 원인 분석
* **마스터 업데이트 실패 시 가드 부재**: KIS API에서 종목 마스터 파일(`zip`)을 받아와 파싱할 때 일시적인 파일 손상, 포맷 불일치 또는 네트워크 오류가 발생할 수 있습니다. 
* **0 오버라이트 현상**: 마스터 파싱 결과 상장주식수가 `0` 또는 `None`으로 변환되거나 `stock_info` 테이블의 `m_vol` (상장주식수) 컬럼이 `0`으로 덮어써지면서, `daily_task.py`에서 당일 종가와 곱해 `mkt_cap`을 산출할 때 `cls_prc * 0 = 0`으로 계산되어 적재되는 악순환이 유발되었습니다.

## 3. 해결 조치 사항
* **자가 치유형 Fallback 로직 반영**:
  * `daily_task.py`의 `mc_records` 시가총액 데이터 빌드 시점에 `shares = stock.get("listed_shares", 0) or 0`이 `0` 이하일 경우, 전체 프로세스를 죽이지 않고 DB 내 해당 종목의 최근 10일 영업일 이내의 정상 적재 이력을 `market_cap_repo`를 통해 역방향으로 탐색합니다.
  * 기존 적재된 이력 중에서 `listed_shares > 0`인 마지막 값을 추출하여 현재 수집의 상장주식수로 적용하고, 경고성 로깅(`logger.info`)을 수행합니다.
* **영향성 복구**:
  * 공공데이터포털 API를 활용하여 2020년 1월부터 2025년 6월까지의 전 종목 과거 시가총액/상장주식수 데이터를 성공률 100%로 복구하여 데이터의 무결성을 전면 보완하였습니다.

## 4. 재발 방지 검증
* 복구 로직이 반영된 `daily_task.py` 코드 기준으로 `pytest` 검증용 모크 테스트를 포함하여 총 99개의 단위/엔드포인트 테스트 케이스가 성공적으로 통과함을 검증하였습니다.
