# [P2ERR-005] KIS API 일봉 거래대금(amt) 및 회전율(turn_rt) 0/NULL 누적 적재 에러

## 1. 에러 현상 및 환경
* **발생 환경**: KDMS 일일 시세 수집 배치 (`daily_task.py`) 실행 환경 (WSL2 / Ubuntu 24.04 LTS)
* **장애 내용**: 
  * `2026-06-17` ~ `2026-06-22` 구간의 수집된 일봉 데이터 (`daily_ohlcv`) 중 `amt`와 `turn_rt` 컬럼이 전체 종목에 대해 `NULL`로 적재됨.
  * `2026-06-23` ~ `2026-06-26` 구간의 수집된 일봉 데이터 중 `amt`와 `turn_rt` 컬럼이 전체 종목에 대해 `0` 및 `0.0`으로 적재됨. (2026-06-26은 도커 이미지 미갱신 상태로 구동되어 재발한 것)

## 2. 발생 원인 분석
* **필드 파싱 누락 및 KIS API 응답 규격 오판**:
  1. **NULL 적재 원인**: `kis_kr_client.py` 내 일봉 수집 함수에서 KIS API 응답 데이터 중 `amt`와 `turn_rt`를 추출해 딕셔너리로 바인딩하는 로직 자체가 없었음.
  2. **0 적재 원인**: `bb4799b` 패치 시 파싱 코드가 추가되었으나, 실제 KIS 일봉 차트 API 응답 필드명은 `acml_tr_pb_amt`가 아니라 **`acml_tr_pbmn`**이었으며, 회전율(`vol_tnrt`) 필드는 일자별 배열(`output2`)에 **존재하지 않았음**. 이에 따라 `dict.get()` 메서드가 `None`을 리턴했고, 디폴트 가드(`or 0` 및 `or 0.0`)에 의해 `0`과 `0.0`으로 강제 적재됨.
  3. **2026-06-26 재발 원인**: 소스 코드는 수정되었으나, 실제 백엔드가 구동되는 Docker 컨테이너 이미지가 빌드/배포 단계에서 누락되어 구버전 코드로 오늘(6/26) 수집 배치가 실행되었음.

## 3. 해결 조치 사항
* **수집기 필드 맵핑 및 태스크 연산 수정**:
  * `kis_kr_client.py`에서 `amt` 파싱 시 **`acml_tr_pbmn`**을 사용하도록 변경.
  * 일봉 차트 응답에 없는 `turn_rt`는 수집 태스크 레이어(`daily_task.py`)로 연산을 위임.
  * `daily_task.py`의 `DailyTask.run` 루프에서 수집 완료된 일봉 리스트를 DB에 넣기 직전, 종목의 정상 상장주식수(`listed_shares`)와 거래량(`volume`)을 이용하여 `turn_rt`를 직접 계산하여 주입하도록 조치.
    * 수식: `turn_rt = (volume / listed_shares) * 100.0` (listed_shares > 0 일 때만)
* **도커 이미지 재빌드 및 서비스 재기동**:
  * 최신 패치가 반영된 백엔드 구동을 위해 도커 컴포즈 빌드를 재수행하고 컨테이너를 재시작함:
    `docker compose up -d --build p2_kdms`
* **테스트 코드 갱신**:
  * `test_kis_kr_client.py` 내 mock 데이터와 검증 단언문(assert)을 수정한 필드명(`acml_tr_pbmn`) 및 `turn_rt` 0.0 기본값에 맞게 업데이트하여 전체 100개 테스트 통과 완료.
* **오염 데이터 범위 백필 (Backfill)**:
  * 범위 기반으로 최적화된 백필 스크립트(`backfill_via_kis.py`)를 임시 작성하여 `2026-06-17` ~ `2026-06-26` 동안의 누락/오염된 3915개 종목(ETF 포함) 데이터를 KIS API 및 직접 연산 로직을 통해 완벽하게 복구 완료.

## 4. 재발 방지 검증
* 도커 재기동 및 6/26 오염 보정 완료 후 DB 검증용 스크립트(`check_daily_ohlcv.py`)를 통해 최근 수집 구간 및 오늘 데이터의 `Amt=Null`/`TurnRt=Null` 건수가 0건으로 정상화되었음을 최종 확인하였으며, `vol > 0` 인 정상 거래 종목의 `amt`와 `turn_rt`가 모두 정상 수치로 채워졌음을 입증함.
