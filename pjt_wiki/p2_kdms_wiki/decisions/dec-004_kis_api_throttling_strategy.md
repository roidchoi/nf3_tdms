# [P2DEC-004] KIS/Kiwoom OpenAPI 안전 마진 속도 제어 및 방어적 시가총액 연산 정책

> **Sub Project**: p2_kdms
> **Status**: active
> **Date**: 2026-05-28
> **관련**: `[[errors/err-001_kis_api_403_forbidden.md]]`, `[[errors/err-002_bigint_out_of_range_in_market_cap.md]]`, `[[interfaces/schema_kdms_db.md]]`

---

## 배경

1. **무제한 연속 호출로 인한 KIS IP 차단**:
   * 기존 KDMS의 OpenAPI 연동 클라이언트는 호출 루프 도중 아무런 지연 처리를 가하지 않았습니다. 이로 인해 한국투자증권(KIS) OpenAPI 게이트웨이가 순간 초당 트래픽 허용 임계치를 넘는 연속 호출을 공격으로 감지하여 당사 IP의 토큰 발급 및 시세 조회를 일시 차단(`403 Forbidden`)하는 대규모 수집 누락(4,422건) 사태가 발생했습니다.
2. **비정상 데이터 유입으로 인한 트랜잭션 전체 롤백**:
   * KIS 마스터 파일에서 일반 주식이 아닌 금융상품(수익증권, 펀드 등) 파싱 오프셋 불일치로 인해 상장주식수(`m_vol`)에 날짜 포맷 메타정보(`20250901000000`, 20조)가 왜곡 저장되었습니다.
   * 이 왜곡 데이터와 당일 주가가 연산되어 PostgreSQL `bigint` 범위(최대 9경)를 넘는 오버플로우를 발생시켰으며, 그 여파로 일일 수집의 마지막 단계인 시가총액 벌크 적재가 중단되고 당일 수집 내용 전체가 유실되었습니다.
3. **Kiwoom OpenAPI 트래픽 초과 예방**:
   * 키움증권 REST API는 공식 규격 상 조회 및 주문 요청 한계치가 초당 5회로 엄격하게 통제됩니다. 이 한계를 초과해 API를 호출할 시 요청 거부 및 차단 오류가 유발될 위험이 큽니다.

## 결정 내용

### 1. KIS API 안전 마진 기반의 호출 속도 제어 (Throttling Delay) 강제
* KIS OpenAPI 라우팅 한계점(실전 20회/초, 모의 2~5회/초) 대비 안전 마진을 충분히 고려하여 요청 성공 직후 강제 지연(`time.sleep`)을 적용합니다.
* **실전 투자(is_mock=False)**: `0.08초` (초당 최대 12.5회 호출 보장)
* **모의 투자(is_mock=True)**: `0.4초` (초당 최대 2.5회 호출 보장)
* 이 속도 정책은 `kis_api_core.py`에서 원자적으로 처리되어, 모든 API 엔드포인트 연동 시 공통 자동 적용됩니다.

### 2. Kiwoom API 안전 마진 기반의 호출 속도 제어 도입
* 키움 REST API의 초당 5회 한계치를 고려하여, 안전 마진(초당 최대 4회 제한)을 보장하는 **0.25초 강제 지연**을 기본으로 도입합니다.
* 이 딜레이 정책은 `kiwoom_api_core.py` 내의 `request()` 반환 직전에 `time.sleep(self.throttle_delay)` 구조로 탑재되어 상위 `KiwoomClient` 등 모든 키움 API 호출 모듈에 일관되게 대칭 상속됩니다.

### 3. 방어적 빅인트 연산 및 보정 규칙 수립
* 데이터베이스 스키마 수정 없이 데이터 보정 처리를 적용해 DB 트랜잭션 안전성을 극대화합니다.
* **상장주식수 한계 제한**: 상장주식수(`shares`)가 1,000억 주(`100_000_000_000`)를 초과하거나 음수일 경우 정상 마스터 범위를 이탈한 파싱 오류로 간주하여 강제로 `0`으로 세팅합니다.
* **DB bigint(9경) 상한 필터링**: 시가총액(`mkt_cap`) 및 거래대금(`amt`) 계산 결과가 PostgreSQL `bigint` 상한값인 9경(`9_000_000_000_000_000_000`)을 초과할 시 강제로 `0`으로 보정 세팅하여, 어떠한 기형적 파싱 오류가 유입되더라도 수집 태스크 E2E 트랜잭션이 성공적으로 마감되도록 보증합니다.

## 영향 범위

- **`tdms_core/p1_shared/p1_shared/api/kis_api_core.py`**: 생성자에 `throttle_delay` 구현 및 API 요청 직후 지연 처리 구현.
- **`tdms_core/p1_shared/p1_shared/api/kiwoom_api_core.py`**: 생성자에 `throttle_delay=0.25` 구현 및 `request()` 직후 지연 처리 구현.
- **`tdms_core/p2_kdms/tasks/daily_task.py`**: 일봉 수집 루프 내 시가총액 계산 시 1,000억 주 초과 및 9경 초과 방어 필터 적용.

## 대안 검토

| 대안 | 거부 이유 |
|---|---|
| KIS IP 차단 시 임의 백오프만 활용 | 한도 초과 차단이 한 번 발생하면 IP가 약 10분간 완전히 고정 차단되므로, 실시간 수집 도중 백오프 재시도만으로는 연속 차단을 극복할 수 없습니다. 요청 자체를 통제하는 Throttling이 무조건 선행되어야 합니다. |
| DB 시가총액 테이블의 numeric 변경 | `daily_market_cap` 컬럼 타입을 `numeric`으로 변경하는 DDL 스키마 변경 시, 하위 USDMS 컴포넌트 전체에 대한 데이터 타입 변경 전파 파급력이 매우 큽니다. 비정상 금융상품 데이터의 마스터 파싱 오차가 근본 원인이므로, 수집 단에서 방어 필터링을 적용하는 것이 아키텍처적으로 비용이 가장 낮고 안전합니다. |
| Kiwoom API 지연 처리를 개별 수집 스크립트에 탑재 | 키움 API를 조회하는 여러 모듈(일봉, 분봉, 계좌 관리 등)마다 중복 구현이 발생하고 지연 시간의 파편화가 발생하므로, 최하단 `KiwoomApiCore.request` 계층에서 일괄 강제하는 것이 아키텍처 결집도 및 중복 제거에 훨씬 합리적입니다. |
